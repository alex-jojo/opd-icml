# OPD H200 实验保存说明

适用版本为 `branch-h200` 的七组统一对照版本，范围是默认 H200 套件、单模型入口和独立 Base 评测。以下是代码定义的产物。某次运行实际完成了哪些阶段、导出了哪些文件，可以用该次 ZIP 的 `EXPORT_MANIFEST.json` 核对。

**默认下载一个结果 ZIP 就能查看训练回答、逐步诊断、评测回答和分数。** 想重新加载某一步的模型，需要事先保留权重。默认只为终点和符合条件的早停点保存可评测权重，评测全部成功后按实验清理。

## 默认七组实验分别保存什么

下表列出不指定 `--scales` 时 H200 总入口实际安排的任务。每组都会保存训练回答、诊断、终点评测回答及评分。表中“早停”指在 FULL 轨迹上选出并评测早停 checkpoint。

| 学生模型 | 终点评测 | 早停 | 额外任务 |
| --- | --- | --- | --- |
| Qwen3 1.7B | 数学 Mean@8 | 有 | 一次复用训练及评测、一次未训练 Base 评测 |
| Qwen3 4B | 数学 Mean@8 | 有 | 一次复用训练及评测、一次未训练 Base 评测 |
| Qwen3 8B | 数学 Mean@8 | 有 | 一次复用训练及评测、一次未训练 Base 评测 |
| Gemma3 12B | 数学 Mean@8 | 有 | 一次复用训练及评测、一次未训练 Base 评测 |
| DeepSeek-Coder 1.3B | 代码 pass@8 | 有 | 一次复用训练及评测、一次未训练 Base 评测 |
| DeepSeek-Coder 6.7B | 代码 pass@8 | 有 | 一次复用训练及评测、一次未训练 Base 评测 |
| DeepSeek-Coder 33B | 代码 pass@8 | 有 | 一次复用训练及评测、一次未训练 Base 评测 |

共七次 FULL 训练，加七次复用训练。七个模型各有 FULL、早停、复用、Base 四行结果，共 28 行。早停沿用对应 FULL 的轨迹，Base 直接加载原始模型，两者都不增加训练次数。下文以 4B 路径举例，其他规模使用各自的目录名。

## 1. 拿到 ZIP 先看哪里

以套件输出 `runs/h200-suite/run1` 为例，压缩包在旁边的 `run1-results.zip`。包内实验文件以 `run1/` 开头。下表的路径从该目录算起，单模型目录内的文件以 4B 为例。

| 想查什么 | 打开哪个文件 | 可以读到什么 |
| --- | --- | --- |
| 本次实际跑了哪些组 | `plan.json`、`status.json`、`logs/` | 计划中的模型、设备和命令，各组实际执行状态及日志。默认七个模型规模共十四次训练，每组各有一次 FULL 和一次复用训练。 |
| 各模型的策略对照 | `rq4_comparison.json` | 按规模列 FULL、早停、复用，另附同一规模的未训练 Base。数学保存五项 Mean@8；代码保存两项 pass@8 及其等权平均。两类任务均记录相对 FULL 的变化与耗时。 |
| 早停选了第几步 | `4b/training/training_records/rq4/early_stop_summary.json` | `rollout_rounds`、`optimizer_updates`、`stop_reason`、`uses_full_endpoint`、`responses_file`。最后一个字段直接指向相对于本组目录的逐题文件。 |
| FULL 最终答对了哪些题 | `4b/eval/final_mean8.jsonl` | 每题的回答和逐样本判分。`4b/eval/final_mean8.summary.json` 给出各题集的题数、回答数和 Mean@8。 |
| 未训练 4B Base 的成绩 | `4b/eval/base/summary.json` | 同一批原始回答的宽松和严格两套成绩。核对表 3 的宽松口径取 `lenient_answers_v1`，和 RQ4 的 FULL 对比取 `strict_last_box`。 |
| 清理了多少模型文件 | `4b/model_cleanup.json` | 清理状态、被删路径、逐文件逻辑字节数和总量。`model_artifact_metadata.json` 另存小型配置及步数等文本。 |

五项是 MATH500、HMMT25 Feb、HMMT26 Feb、AIME26 和 Minerva。默认训练后数学评测另含 AMC23。汇总中的 Mean@8 以 0–1 表示，乘 100 得到百分数。每题八个回答分别判分，八个里答对一个贡献 1/8。

## 2. 每轮训练及论文诊断

以下路径相对于单组实验目录，例如 `run1/4b/`。FULL 每轮 rollout 做一次参数更新。复用组单独放在例如 `run1/4b-reuse/`，每轮做两次更新，所以阅读数据时要区分轮号和更新号。

| 文件或目录 | 写入时机 | 保存内容 |
| --- | --- | --- |
| `training/training_records/1.jsonl`、`2.jsonl` 等 | 每轮 rollout | 一行一个训练样本。`input`、`output` 是解码后的提示词和学生回答，另有 `gts`、`score`、`step`。代码任务还记录题目来源。 |
| `training/training_records/post_update_0001.json` 等 | 每轮更新完成 | 完成标记和该轮指标，包括可用的 KL、梯度诊断、阶段耗时、token 数和吞吐。 |
| `training/training_records/rq1_step_XXXX.json` | 默认抽样配置下按更新写入 | 当前批次高 KL token 的占比、hidden 梯度能量、抽样估计的参数梯度能量。样本列可对齐回答行、token 位置、ID、KL、能量和抽样权重。第 1 步的 KL 阈值保留供以后各步对比。 |
| `training/training_records/rq2/probe_initial.npz`、`step_XXX.npz` | 固定 probe 初始化，以及每次 FULL 更新后 | 固定输入和初始 hidden、相对初始状态的位移 RMS、特征值谱、累计能量、当前前 128 个方向。第 10 步建立固定参考基，之后可查覆盖率和子空间重合度。 |
| `training/training_records/rq2/gradient_XXX.npz` | 每次 FULL 更新 | 产生本次更新的 hidden 梯度谱及前 128 个方向的能量占比。从第 11 次更新起可查对第 10 步参考基的覆盖率。用 `checkpoint_before` 对齐梯度测量时的模型。 |
| `training/validation128/split.json`、`checkpoint_XXX.json` | 固定验证集划分及预定测量点 | 划分索引、题目哈希。测量点保存 128 个回答的 token ID、源题索引、长度、KL、得分和整组均值。默认 FULL 有第 106 步终点读数。 |
| `training/training_records/rq2/reference_010.npz` | 第 10 步 | 保存固定参考。各步位移文件还记录相对第 10 步及上一步的增量、RMS 和参考基能量覆盖率。恢复后的第一次相邻步测量可能标为不可用。 |
| `training/training_records/parameters/update_*.json` | 已有验证诊断步 | 按层和参数组保存实际权重更新的非零坐标数、正负计数、L1/L2、RMS、最大变化、能量占比和方向余弦。 |
| `training/training_records/rq3/checkpoint_XXX.json` | 默认 FULL 在第 0、10、…、100 步之后的下一次更新 | 同一回答在更新前后的 KL、差值 `gain`、正增益比例。用 `response_row` 和 `response_sha256` 与同一测量点的验证回答关联。 |
| `training/replication/`、`training/assets/` | 每轮或配置的诊断步 | `round_XXX.json` 记录轮号、更新数、更新前 KL 和梯度范数。详细测量还写入 `token_audit/`、`gradient_moments/`、`gradient_scopes/`、`token_group_scopes/`、`motion/`。跨批梯度、路径方差和验证迁移按启用项写入 `gradient_study/checkpoint_XXX/`。参考基写入 `assets/full_step10_rank128.npz`。 |

对称二阶矩按上三角无损保存，用 ZIP 自带的 `READ_MOMENTS.py` 中的 `load_moment` 可还原稠密矩阵。默认省略完整 hidden 梯度样本向量；参数梯度抽样的能量、位置和权重仍保留。

**这里的 `rq3/checkpoint_050.json` 是测量记录。** 它能回答“第 50 步附近验证 KL 怎么变”，不能用来加载第 50 步的模型。同样，默认 RQ1 每步最多抽 256 个 token 保存参数梯度能量及权重，逐 token 的完整模型参数梯度向量无法从这些标量恢复。

## 3. 早停、终点和复用具体怎么存

1. 七组各自的 FULL 每 5 次更新检查稳定性，最早在第 15 步具备完整窗口。每次判定写入 `training/training_records/rq4/early_stop_XXX.json`，可追溯比较了哪些步、各项阈值和判定结果。
2. 首次提前触发时，保存**当次更新后的学生权重**到 `training/checkpoints/early_stop/actor/`，并写 `early_stop/selection.json`。这一份含模型分片和加载配置，省去优化器状态。FULL 接着训练至 106 轮，终点权重在 `training/checkpoints/global_step_106/actor/`。
3. 训练结束后，提前触发的早停模型先合并、评测，逐题结果和汇总在 `eval/early-stop/`。临时合并副本释放后再合并 FULL 到 `merged/`。如果选中预算终点，两个策略共用终点的数学回答或代码生成结果；此时没有单独一套早停回答属正常。
4. 独立的复用训练做 53 轮 rollout、106 次更新。在第 5、10、…、50、53 轮，`training/training_records/rq4/reuse_round_XXX.json` 保存同一批回答在两次更新前后的三个 KL 值和第二次更新的增益。终点目录编号为 `global_step_53`。
5. `rq4_training_time.json` 记录训练尝试及耗时。`training/training_records/rq4/summary.json` 保存 FULL 或复用本组成绩。早停另写 `early_stop_summary.json`，其 `source_strategy=full`。提前触发时耗时取 FULL 开始到早停权重写完的累计训练时间，合并、评测及 Base 用时另计。无法还原完整训练时间时，相应字段为 `null`。

## 4. 评测原文、判分和复算

| 评测 | 结果文件 | 如何追溯 |
| --- | --- | --- |
| 训练后数学 Mean@8 | `eval/final_mean8.generations.jsonl`、`final_mean8.generations.meta.json`、`final_mean8.grading.jsonl`、`final_mean8.jsonl`、`final_mean8.summary.json` | 先保存八个回答及生成配置，再写判分进度和最终逐题结果。元数据含题集、模型文件和采样身份信息。严格判分的逐样本结果在 `acc_list`。提前触发的早停评测沿用相同文件名，放在 `eval/early-stop/`。 |
| 四组数学 Base | `eval/base/responses.jsonl.gz`、`responses.meta.json`、`scores.jsonl`、`summary.json` | 压缩原文每题一行，含问题、参考答案、实际提示词、八个回答、长度及停止原因。判分用从零起的 `index` 关联原文，用 `generation_sha256` 核对来源。并行判分的物理行序可能不同。 |
| 代码 pass@8 | `eval/code_pass8/run.json`、`summary.json`，下设 `livecodebench/` 和 `humanevalplus/` | FULL 提前触发时，早停评测另存于 `eval/early-stop/code_pass8/`。早停汇总的 `responses_files` 按题集给出回答路径。每个题集的 `generations.jsonl` 保存生成，`grades.jsonl` 按 `task_id` 保存判题结果，`summary.json` 给出 pass@8，`grading.complete.json` 标记判题完成。每题八个候选中至少一个通过，即该题通过。 |

默认套件为七组各评一次未训练学生模型，结果进入同一总 ZIP 的 `<规模>/eval/base/`。数学组使用论文五项 Mean@8 和两种判分。三组 DeepSeek 使用与训练后相同的 chat 模板、停止符及两个代码 benchmark；生成、判题和完成凭据在 `eval/base/code_pass8/<题集>/`，Base 汇总在 `eval/base/summary.json`。

已有训练结果时可以单独补测。例如在项目根运行 `python scripts/evaluate_base.py --scale deepseek-coder-33b`，会用可见 GPU 生成答案并判题。可以通过 `--output` 指定已有 FULL 目录的 `eval/base` 子目录。默认独立输出为 `runs/h200/<规模>/<math或code>-base/`，默认在旁边打包。

## 5. 磁盘和 ZIP 的边界

| 情况 | 磁盘上会留下什么 | 下载后还能做什么 |
| --- | --- | --- |
| 默认整组评测成功 | 验证评测结果后清理本组 `training/checkpoints/` 和 `merged/`。保留统计、回答、日志、清理凭据。代码组等待 CPU 判题完成。 | 用结果 ZIP 重算指标、画图、核查原文。重新生成回答需要另有对应权重。 |
| 只训练、代码只生成，或评测中断 | checkpoint 保留，可供后续合并、评测或重试。数学的 `generate` 阶段同时评分，成功后会触发清理。 | 阶段性 ZIP 可能只有部分结果，查看清单的 `phase` 和各评测完成文件。 |
| 指定 `--keep-model-files` | 评测成功仍在服务器保留 checkpoint 和最终合并权重。单模型的 `--model-artifacts-root` 可指定外部位置；新运行拥有的外部目录也按相同规则清理，缺少归属标记的旧目录会保留。 | 结果 ZIP 仍排除模型。如需带走模型，须另取权重目录。 |
| 指定 `--save-freq N` | 周期保存可续训 checkpoint，额外包含优化器、训练附加状态和数据加载进度。默认模型导出用于评测。 | 用服务器保留的可续训 checkpoint 恢复训练。 |

任何提前触发早停的 FULL 组，在合并评测阶段要同时容纳**终点分片、早停分片和当前正在评测的一份合并权重**。多个实验并行时，占用会叠加。共享模型缓存与原始数据继续占盘。打 ZIP 时源结果与新 ZIP 共存，替换旧 ZIP 前旧包也仍占空间。套件默认监测文件系统 5 GiB 余量，环境变量 `OPD_MIN_FREE_GIB` 可调整；该阈值不能据以推算整次运行的峰值。以 33B、FP32 分片和 BF16 合并权重估算，提前触发时模型副本合计约 330 GB（307 GiB），另需预留原始模型缓存、数据、诊断及 ZIP 的空间。默认 33B 的 FULL 判题并清理后才开始 33B 复用训练。

默认打包会收集允许格式的 JSON、JSONL、压缩文本、NPZ、NPY、配置和日志。权重、checkpoint 目录、符号链接、W&B 本地目录、凭据和嵌套 ZIP 均被过滤。例如 `training/replication/training_motion_panel.pt` 可留在服务器上，但因 `.pt` 后缀被排除；可随包查看的固定 probe 在 `training/training_records/rq2/probe_initial.npz`。包根目录的 `EXPORT_MANIFEST.json` 列出每个导出文件的路径、原始字节数及 CRC32。`model_cleanup.json` 统计的是被清理文件的逻辑大小，实际峰值还受缓存、并发和文件系统影响。
